	요약문	
		
요약문
‘‘운명을 만드는 공간’은 사용자의 생년월일과 성별을 기반으로 사주팔자를 계산하고, 이를 토대로 성격과 오행적 특성을 분석하여 시각적으로 표현하는 개인 맞춤형 운세 애플리케이션입니다. 단순한 사주 조회 기능을 넘어 궁합 분석과 커뮤니티 기능을 결합함으로써, 사용자가 자신의 성향을 이해하고 다른 사람과 교류할 수 있는 공간을 제공하는 것을 목표로 하고 있습니다.
시스템은 클라이언트-서버 구조로 설계되었으며, 클라이언트는 Flutter 프레임워크를 이용하여 크로스플랫폼 환경에서 구현되었습니다. 서버는 Python 기반으로 구축되어 사주 분석, 궁합 계산, 사용자 관리 등의 핵심 로직을 처리하며, 데이터는 관계형 데이터베이스(RDB) 구조로 관리됩니다. 또한 효율적인 검색과 정렬을 위해 B-Tree 인덱스와 Full-Text Search 기법이 적용되었습니다.
주요 기능으로는 사주 조회, 궁합 분석, 커뮤니티, 실시간 채팅, 알림 및 설정 기능이 포함되어 있습니다. 사용자는 자신의 사주 정보를 입력하여 분석 결과를 확인하고, 다른 사용자나 유명인과의 궁합을 비교할 수 있습니다. 커뮤니티 게시판에서는 글 작성, 댓글, 검색, 친구 추가 등의 기능을 통해 활발한 상호작용이 가능하며, 알림 및 피드백 기능을 통해 사용자 경험을 향상시킵니다.
핵심 알고리즘으로는 해시 기반 탐색(Hashing) 을 사용하여 평균 O(1)의 빠른 검색 성능을 구현하였으며, 게시물 검색에는 MySQL Full-Text Search 기능을 적용하여 효율적인 키워드 검색을 지원합니다. 또한 인기 게시글은 Min-Heap 기반 Top-K 정렬 알고리즘을 통해 실시간으로 처리되도록 하였습니다.
화면 설계는 사용자 중심의 인터페이스를 위해 홈 화면, 게시판 화면, 더보기 화면의 세 가지 구조로 구성되었습니다. 홈 화면에서는 사주 관련 주요 기능에 쉽게 접근할 수 있으며, 게시판 화면에서는 다른 사용자와의 교류가 가능하고, 더보기 화면에서는 프로필 관리 및 앱 설정이 가능하도록 설계되었습니다.
이 프로젝트는 사주 명리학의 전통적 이론을 현대적인 IT 기술과 융합하여, 분석과 소통을 동시에 구현한 지능형 운세 플랫폼으로 설계되었습니다. Flutter, Python, RDB, 해시 탐색 등의 기술을 활용하여 사용자 맞춤형 서비스와 효율적인 데이터 처리를 동시에 실현한 것이 본 프로젝트의 핵심적인 특징입니다.

Abstract
The Space That Creates Destiny’ is a personalized fortune-telling application that calculates a user’s Four Pillars of Destiny (Saju) based on their date of birth and gender, and visually represents their personality and elemental characteristics (Wood, Fire, Earth, Metal, Water). Beyond simple fortune calculation, the application integrates compatibility analysis and community features, aiming to provide users with a space where they can better understand themselves and interact with others.
The system is designed using a client–server architecture. The client is developed with the Flutter framework, enabling cross-platform operation on Android and iOS. The server is built with Python, handling core logic such as fortune analysis, compatibility calculation, and user management. Data is managed through a Relational Database (RDB) structure, and efficient search and sorting are achieved using B-Tree indexing and Full-Text Search techniques.
The main features include fortune analysis, compatibility evaluation, community interaction, real-time chat, and notification and settings management. Users can input their birth information to receive analytical results, compare their compatibility with other users or celebrities, and engage in discussions through the community board. The application also enhances user experience through interactive features such as commenting, searching, friend requests, and feedback submission.
The core algorithms utilize hash-based searching (Hashing) to achieve an average O(1) search performance. For post searching, MySQL Full-Text Search is implemented to support efficient keyword retrieval, while popular posts are dynamically managed using a Min-Heap–based Top-K sorting algorithm.
The user interface (UI) is designed with a user-centric approach, consisting of three main sections: the Home Screen, the Community Board, and the More Menu. The home screen provides quick access to key features, the board allows user interaction and discussion, and the “More” section supports profile management and app settings.
This project combines the traditional theory of Saju (Four Pillars of Destiny) with modern IT technologies, creating an intelligent fortune-telling platform that integrates both analysis and communication. By utilizing Flutter, Python, RDB, and Hashing techniques, the system successfully achieves both personalized services and efficient data processing, establishing a modern, interactive environment for users to explore their destiny.

1.1.	프로젝트 개요 및 주안점 (수정)
본 프로젝트는 전통적인 사주 분석 기술을 현대적인 모바일 플랫폼에 구현하여 개인 성향 및 운세 정보를 제공합니다. 주요 기능으로는 사주 보기, 궁합 보기, 그리고 유명인과의 궁합 보기를 통해 사용자에게 맞춤형 분석 결과를 제공합니다. 분석된 사주 결과는 오행 캐릭터화를 통해 직관적으로 시각화되며, 사용자들은 게시판을 통해 소통할 수 있습니다.
우리는 유명인과의 궁합 보기와 오행 캐릭터화를 통해 서비스의 차별화된 엔터테인먼트 요소를 강화하는 것에 중점을 두었습니다. 이는 사용자에게 재미와 흥미를 제공하여 서비스 유입을 확대하는 핵심 요소입니다. 또한 게시판 기능을 중심으로 커뮤니티 플랫폼을 구축하여 사용자 간의 소속감을 형성하고 서비스에 대한 지속적인 참여를 유도하는 것을 주요 목표로 설정했습니다



1.2.	분석 및 필요성 (수정 주석)
최근 MZ세대를 중심으로 자기 이해와 관계 분석에 대한 관심이 증가하고 있습니다. 대표적으로 MBTI 검사는 2020년 이후 국내외에서 폭발적인 인기를 끌며, 관련 커뮤니티와 콘텐츠 시장이 확장되었습니다.(윤소희, 2024) 구글 트렌드 및 네이버 데이터랩 분석에 따르면, 2022년 한국 내 'MBTI' 검색량은 전년 대비 2배 이상 증가하여 이러한 흐름을 뒷받침합니다.
 
<그림 1 ‘MBTI’ 검색량>

이와 더불어, 사주 앱 시장 역시 성장세를 보이고 있습니다. 국내 점술·사주 시장 규모는 약 1조 4,000억 원으로 보고됩니다. (정원욱, 2024) 실제로 대표적인 사주 앱인 ‘포스텔러’는 100만 건 이상의 다운로드를 기록하며, 젊은 세대가 손쉽게 사주를 접하는 어플로 자리 잡았습니다. 특히 네이버와 카카오 등 주요 플랫폼에서 제공하는 사주/궁합 서비스도 높은 이용률을 보이며, 사주가 단순 오락을 넘어 자기 이해와 관계 탐색의 도구로 활용되고 있음을 보여줍니다.
 그러나 기존 앱들은 ‘운세 제공’에 머물러 있어 사용자 간 소통, 소속감 형성, 재미 요소가 부족한 실정입니다. 따라서 본 프로젝트는 MBTI처럼 재미와 커뮤니티적 소속감을 제공하면서, 사주의 정통성과 개인화 요소를 결합하여 차별화된 가치를 창출하고자 합니다. 이를 통해 단순 운세 제공을 넘어서 사용자 참여와 몰입을 강화하는 새로운 형태의 사주 앱을 제안합니다.

1.3.	목표 및 기대효과
본 프로젝트는 전통적인 사주 분석 기술을 현대적인 모바일 플랫폼에 구현하여 개인 성향 및 운세 정보를 제공합니다. 제공된 핵심 알고리즘을 활용해 사주 보기 및 궁합 보기 결과를 텍스트와 오행 캐릭터로 시각화함으로써 직관적이고 차별화된 사용자 경험을 제공합니다. 또한 유명인과의 궁합 보기를 통해 엔터테인먼트 요소를 확장합니다. 게시판을 통한 커뮤니티 기능으로 이용자 간 지속적인 상호작용을 촉진합니다. 오행 캐릭터를 프로필과 게시판에 적용해 소속감을 강화함으로써 서비스 확산성을 높입니다.

3.	주요 기능 목록

기능	상세설명

앱 진입 및 로그인	앱 실행 시 간단한 진입 애니메이션을 출력한 뒤 로그인 화면으로 이동한다. 기존 사용자일 경우 저장된 토큰을 확인해 자동 로그인 처리하고, 신규 사용자는 회원가입 화면으로 분기한다. 로그인 정보는 Flutter 앱에서 입력 받아 서버(Firebase Auth 또는 자체 DB)로 전달하여 인증한다. 인증이 완료되면 홈 화면으로 전환한다.
사주 입력 및 조회	사용자가 생년월일·시간·성별을 입력하면 사주 계산 모듈로 전달하여 사주팔자를 생성한다. 생성된 사주는 일간·오행 정보를 포함하며, 계산 결과는 JSON 구조로 반환한다. 사용자가 이전에 사주를 본 적이 있는 경우에는 입력 화면 대신 바로 결과 화면으로 이동하도록 분기한다.

오행 캐릭터 시각화	사주 분석 결과에서 뽑아낸 오행(목·화·토·금·수)을 기준으로 미리 정의된 캐릭터 리소스를 매핑하여 화면에 보여준다. 캐릭터는 사용자 프로필에도 자동으로 적용되며, 커뮤니티 게시판에서 사용자 아이콘으로 함께 노출되도록 한다. 이렇게 해서 같은 오행끼리 소속감을 느낄 수 있게 한다.

사주 궁합 보기	사용자가 ‘궁합 보기’ 버튼을 누르면 친구 목록에서 대상을 선택하거나, 대상 정보(생년월일·성별)를 직접 입력할 수 있는 팝업을 띄운다. 두 사람의 사주 정보를 비교해 궁합 점수와 설명을 생성하고, 동시에 오행 상생/상극 관계를 보여준다. 

유명인과 사주 궁합	앱 내부에 미리 저장해 둔 유명인 사주 데이터를 불러와 사용자의 사주와 비교한다. 유명인은 오행별 대표 인물로 분류하여 사용자가 오행을 선택하면 해당 그룹의 유명인이 보이도록 구성한다. 

커뮤니티(게시판)	게시판 상단에는 네비게이션 바를 두어 ‘최근 글’, ‘내가 쓴 글’, ‘글쓰기’를 빠르게 전환할 수 있게 하고, 그 아래에는 검색창과 최근 게시글 목록을 보여준다. 게시글은 작성 즉시 DB에 저장되고, 실시간으로 게시판에 반영되도록 한다. 게시글에는 좋아요, 댓글, 신고, 스크랩 기능을 제공해 사용자 간 상호작용을 강화한다.

실시간 채팅	사용자가 다른 사용자의 프로필을 열었을 때 ‘친구 추가’와 ‘채팅 보내기’ 버튼을 함께 보여준다. 채팅을 선택하면 1:1 대화방을 생성하며, 최근 대화 내역은 대화 목록 화면에 별도로 저장·표시한다. 채팅은 실시간 전송이 가능한 메시지 DB 기반으로 한다.

알림 및 설정	앱 내에서 발생하는 주요 이벤트(댓글 달림, 친구 요청, 궁합 요청 등)를 알림으로 받을 수 있도록 알림 설정 화면을 제공한다. 설정 화면에서는 프로필 수정, 약관 보기, 개인정보처리방침 보기, 알림 on/off 등을 한 번에 할 수 있도록 한다.
피드백 기능	사용자가 앱 사용 중 불편한 점을 개발자에게 직접 보낼 수 있는 간단한 폼을 제공한다. 입력된 내용은 서버로 전송되어 관리자 페이지에서 확인할 수 있도록 하며, 필요 시 이메일로도 전달되도록 한다.

4.1.	아이디어 창출
 
<그림 1 아이디어 마인드맵>

저희 팀은 사주 애플리케이션에 추가되면 좋을 기능을 떠올리며 다양한 아이디어를 논의했습니다.

먼저 사주 앱에서 필수적이라고 생각하는 개인 사주와 관계 사주는 포함하기로 하였습니다.

첫 번째로 나온 아이디어는 ‘사주 소개팅’이었습니다. 이는 사용자가 사전에 저장되어 있는 정보끼리 관계 사주를 봐주면서 높은 궁합 점수가 나온 사람끼리 소개팅 매칭을 하는 시스템입니다. 이를 통해 다른 소개팅 어플과의 차별점을 두었습니다.

두 번째로 나온 아이디어는 ‘오행 캐릭터화’입니다. 개인 사주 분석을 통해 나온 오행(물, 불, 나무, 금, 흙)의 속성들을 캐릭터화 하는 것입니다. 이는 기존 MBTI와 같이 사용자들에게 재미와 소속감을 느끼게 해줄 수 있습니다.

세 번째로 제시된 아이디어는 ‘직업 추천’입니다. 이 기능은 개인 사주를 통해서 나온 사주 내용과 오행 속성을 토대로 사용자에게 적합한 직업을 추천해주는 기능입니다.

네 번째로 제시된 아이디어는 ‘게시판’입니다. 이 기능은 사주에 관한 의견 뿐만 아니라 잡담이나 질문 등 다양한 소통의 공간을 제공합니다. 게시판의 특징은 팀원이나 룸메이트와 같이 인원을 모집할 때 MBTI를 고려하여 모집하는 거와 같이 사주를 접목하여 사용자가 더욱 좋은 선택을 할 수 있게 도와줍니다. 

다섯 번째로 제시된 아이디어는 ‘유명인과 궁합보기’입니다. 이 기능은 사용자의 사주 정보와 사전에 저장된 유명인의 사주 정보를 비교하여 궁합을 보는 시스템입니다. 좋아하는 유명인과의 가상적인 궁합을 확인하며 사용자에게 재미를 주고, 이 과정에서 자신의 사주 속성에 대한 이해도도 높일 수 있습니다. 이는 기존의 다른 서비스에서는 찾아보기 힘든 독특한 콘텐츠를 제공하여 사용자 유입에 기여할 수 있습니다.

다섯 가지 아이디어를 가중치 분석을 통해 최종적으로 어떤 아이디어가 가장 실현 가능하고 사용자에게 유용한지 평가한 후 애플리케이션에 반영할 기능을 결 정하기로 했습니다.

	수익성: 수익 모델과 효과적으로 연계되어 앱의 이익에 기여하는가?
	차별성: 다른 사주 앱 대비 독창적인 가치를 제공하는가?

각 기준에 가중치를 부여한 이유는 다음과 같습니다. 먼저, 프로젝트는 한정된 개발 기간을 가지고 있으므로, 주어진 시간 내에 구현 가능 여부가 가장 중요한 요소로 판단되어 개발 난이도에 30의 가중치를 부여했습니다. 만족성은 사용자에게 얼마나 만족스러운 경험을 제공하는 것이 프로젝트의 핵심이므로, 이 역시 30의 가중치를 할당했습니다. 수익성과 차별성은 앞선 두 기준보다는 중요도가 낮다고 판단하여 각각 20의 가중치를 부여했습니다.

'사주 소개팅' 기능은 오행캐릭터화와 연계하여 사용자들이 자신의 오행 특성을 바탕으로 궁합을 확인할 수 있어 사용자 만족도에서 +1점을 받았습니다. 하지만 수익 모델이 명확하지 않아 수익 잠재성에서 -1점을 받았습니다.

'직업추천' 기능은 오행캐릭터의 특성을 바탕으로 직업을 추천하는 기능으로 개발 난이도가 상대적으로 낮아 +1점을 받았지만, 사용자 만족도와 수익 잠재성에서는 -1점을 받았습니다. 하지만 오행캐릭터와 연계한 직업 추천은 차별적인 기능으로 +1점을 받았습니다.

'유명인과 궁합보기' 기능은 오행캐릭터화와 연계하여 유명인과의 궁합을 보여주는 기능으로, 복잡한 데이터베이스 구축이 필요해 개발 난이도에서 -1점을 받았습니다. 하지만 사용자 만족도와 수익 잠재성, 차별성에서는 모두 +1점을 받았습니다.

최종 점수 계산:
'사주 소개팅' 기능: +1 + (-1) + 0 + 0 = 0점
'직업추천' 기능: +1 + (-1) + (-1) + 1 = 0점
'유명인과 궁합보기' 기능: (-1) + 1 + 1 + 1 = +2점

퓨(pugh) 방법을 통해 세 기능을 비교해 본 결과 '유명인과 궁합보기' 기능이 +2점으로 가장 높은 점수를 받았습니다. 이는 다음과 같은 이유로 인한 것입니다:

1. 사용자 만족도: 유명인과의 궁합은 사용자들의 높은 관심을 끌 수 있는 재미있고 흥미로운 기능
2. 수익 잠재성: 유명인과의 궁합 기능은 프리미엄 콘텐츠로 활용 가능하여 수익 창출에 효과적
3. 차별성: 오행캐릭터화와 연계한 유명인 궁합 기능은 기존 사주 앱과 차별화되는 혁신적인 기능
4. 마케팅 효과: 유명인과의 궁합 기능은 앱의 홍보와 사용자 유입에 매우 효과적

따라서 사주 분석 앱의 핵심 기능으로 '유명인과 궁합보기' 기능을 최종 채택하였습니다.

4.4.	기능 선정
사주 분석 앱 개발을 위해 적합한 플랫폼을 선택하기 위해 퓨(pugh) 방법을 사용하여 플랫폼을 비교 분석하였습니다.

퓨(pugh) 방법에서 사용할 비교 기준은 다음과 같습니다.
	개발 난이도: 기준 안 대비 더 쉽게 구현할 수 있는가?
기준 선정 이유: 기준 안 대비 개발 난이도가 낮아 안정적으로 기능을 구현할 수 있는지 평가하기 위해 선정했습니다.
	개발 효율성: 정해진 개발 기간 내에 완성도 높은 앱을 개발할 수 있는가?
기준 선정 이유: 사주 분석 앱을 구현하는 데 있어 정해진 기간 내에 개발이 가능한지, 그리고 이 과정에서 발생할 수 있는 기술적 복잡성을 평가하는 것이 중요합니다. 기술적 구현이 어렵거나 복잡하면, 개발 기간이 늘어날 수 있고, 이는 전체 프로젝트 일정에 영향을 미칠 수 있습니다.
	성능: 기준 안 대비 프레임 속도, 메모리 사용량, 앱 구동 속도 등이 더 우수한가?
기준 선정 이유: 기준 안 대비 앱 구동 및 반응속도, 리소스 효율성 등 성능 지표가 우수하여 사용자가 느끼는 만족도를 높이는지 비교하기 위해 선정했습니다. 
	안정성: 기준 안 대비 버그 발생률이 낮고 기술적 위험이 더 적게 발생하는가?
기준 선정 이유: 기준 안 대비 시스템 충돌이나 오류 없이 높은 신뢰도로 작동하며, 기술적 위험을 더 적게 관리할 수 있는지 비교하기 위해 선정했습니다.
크로스 플랫폼이고 개발의 효율성과 성능 균형점을 제공하는 Flutter를 기준으로 이를 다른 세부 내용을 분석하는 기준으로 선정하였습니다.
	Flutter (기준): Dart언어를 사용하여 개발 가능한 크로스 플랫폼입니다.
	React Native: JavaScript/TypeScript를 사용하여 개발 가능한 크로스 플랫폼입니다.
	Native (Kotlin/Swift): android는 주로 Kotlin/Java, iOS는 Swift/Objective-C를 사용하여 각 OS에 맞는 최적화된 앱을 개발 가능한 네이티브 방식입니다

Flutter는 크로스 플랫폼 개발의 표준으로 설정하여 기준점(S)으로 두었습니다. React Native는 JavaScript 기반으로 웹 개발자들이 쉽게 접근할 수 있지만, 네이티브 브릿지를 통한 통신으로 인한 오버헤드로 성능과 안정성에서 -1점을 받았습니다. Native는 각 플랫폼에 최적화되어 있지만, 두 개의 별도 앱을 개발해야 하므로 개발 난이도와 효율성에서 -1점을 받았습니다.

최종 점수 계산:
Flutter (기준): 0점 (기준점)
React Native: 0 + 0 + (-1) + (-1) = -2점
Native (Kotlin/Swift): (-1) + (-1) + 0 + 0 = -2점


퓨(pugh) 방법을 통해 세 플랫폼을 비교해 본 결과 Flutter가 0점으로 가장 높은 점수를 받았습니다. React Native와 Native는 각각 -2점으로 Flutter에 비해 열등한 것으로 평가되었습니다. 이는 다음과 같은 이유로 인한 것입니다:
1. 개발 효율성: 단일 코드베이스로 Android와 iOS 모두 지원하여 개발 시간과 비용을 절감
2. 성능: 네이티브에 가까운 성능을 제공하면서도 크로스 플랫폼의 장점을 유지
3. 안정성: Google의 지속적인 지원과 활발한 커뮤니티로 안정적인 개발 환경 제공
4. 사주 앱 특화: 복잡한 차트와 그래프 UI 구현에 적합한 위젯 시스템으로 사주 분석 앱에 최적화

따라서 사주 분석 앱 개발을 위한 플랫폼으로 Flutter를 선택하였습니다.

7.	모듈별 상세 설계
7.1.	핵심 알고리즘
7.1.1.	유저 탐색

사용자의 단건 조회(user_id 또는 username 기반)는 앱의 권한 확인 등에서 매우 빈번하게 발생하며 지연 시간에 민감합니다.

이를 해결하기 위해 순차 탐색(Sequential Search), 정렬 리스트 + 이진 탐색(Binary Search) 등 여러 대안을 고려했습니다. 최종적으로 앱 계층(Application Layer)에서는 해싱(Hashing)을 기본 조회 방식으로 채택하고, 영속 계층(Persistence Layer)에서는 데이터베이스의 B-Tree 인덱스를 활용하기로 결정했습니다.

해싱은 평균 $O(1)$의 시간 복잡도로 응답 시간을 최소화할 수 있으며, DB의 PK 인덱스는 데이터 신뢰성과 일관된 조회 성능을 보장합니다. 다만, 앱 계층에 캐시를 도입할 경우 데이터 동기화 및 만료(Eviction) 전략이 필요합니다.

또한, 이름 접두사(Prefix)를 이용한 오토컴플릿 기능은 초기에는 정렬 리스트와 이진 탐색으로 구현하되, 향후 서비스 규모가 확대되면 Trie 자료구조나 전용 검색 엔진으로 승격하는 것을 고려합니다.

7.1.2.	게시물 검색

게시판의 핵심 요구사항은 제목과 본문(content)에 대한 키워드 검색 및 정렬입니다.

초기 릴리스는 운영 복잡도를 최소화하기 위해 ElasticSearch와 같은 전용 검색 엔진 대신, 데이터베이스 내장 FTS(Full-Text Search) (예: MySQL FULLTEXT)를 채택하기로 결정했습니다. LIKE '%keyword%'를 사용하는 순차 탐색은 인덱스를 활용할 수 없어 성능이 저하되며, 일반 B-Tree 인덱스는 LIKE 'keyword%' 같은 접두사 검색만 지원하는 한계가 있습니다.

내장 FTS는 추가 인프라 구축 없이 우수한 검색 품질과 성능을 제공합니다. 다만, 토큰화(Tokenizing)나 불용어(Stopword) 등에 대한 튜닝이 필요할 수 있으며, 향후 트래픽 증가 시 전용 검색 엔진으로의 승격과 ETL 파이프라인 구축을 고려해야 합니다.

7.1.3.	기타 적용 지침

정렬 및 페이지네이션: 게시판의 일반적인 정렬(최신순, 인기순)은 created_at, like_count 컬럼에 B-Tree 인덱스를 생성하여 $O(\log n + k)$ (k=페이지 크기)의 복잡도로 지원합니다.

Top-K (실시간 인기글): 실시간 인기글은 앱 캐시 레벨에서 Min-Heap(최소 힙) 자료구조를 사용하거나, DB의 ORDER BY like_count DESC LIMIT K 쿼리를 조합하여 구현합니다.

소규모 도메인 매핑: saju_core의 오행 매핑이나 CharacterInfo 조회처럼 변경이 적은 정적 데이터는 해시맵(Python Dictionary)을 사용하여 $O(1)$의 속도로 조회합니다.
