# 탐색/검색 알고리즘 Big-O 근거 요약

복잡도와 구현 난이도, 운영 복잡도를 3축으로 간단 비교합니다.

## 1) 유저 탐색(단건/식별자 기반)

| 후보 | 조회 복잡도 | 업데이트 복잡도 | 구현 난이도 | 운영 복잡도 | 비고 |
|---|---|---|---|---|---|
| 순차 탐색 | O(n) | O(1) | 매우 낮음 | 낮음 | 데이터 증가 시 부적합 |
| 정렬+이진 탐색 | O(log n) | O(n) (삽입) | 낮음 | 낮음 | 오토컴플릿 범위 탐색 우수 |
| 해싱(앱 캐시) | 평균 O(1) | 평균 O(1) | 낮음 | 중간(캐시 동기화) | 선택 |
| RB-Tree(정렬 맵) | O(log n) | O(log n) | 중간 | 중간 | 파이썬 표준 부재 → 라이브러리 필요 |

결론: 해싱 + DB PK/B-Tree.

## 2) 게시물 검색(키워드/랭킹)

| 후보 | 질의 복잡도 | 인덱싱 비용 | 구현 난이도 | 운영 복잡도 | 비고 |
|---|---|---|---|---|---|
| 순차 포함 검색 | O(n·m) | 없음 | 매우 낮음 | 낮음 | 실사용 불가 성능 |
| LIKE+일반 인덱스 | O(n) 근사 | 낮음 | 낮음 | 낮음 | 간단하지만 품질 한계 |
| DB 내장 FTS | O(log n) + 랭킹 | 중간 | 낮음 | 낮음 | 선택(초기) |
| ElasticSearch | 분산 검색 | 중~고 | 중간 | 높음 | 확장 시 선택 |

결론: 초기 DB 내장 FTS → 확장 시 ElasticSearch 승격. 정렬/페이지네이션은 B-Tree 인덱스로 처리.
